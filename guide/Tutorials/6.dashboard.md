# Discord bot dashboard (starter plan)
Yes — you can absolutely build a Discord bot dashboard.

This tutorial gives you a practical **MVP plan** so you can start simple and expand safely.

## What a dashboard usually includes
A Discord bot dashboard is a website where server admins can:

1. Sign in with Discord OAuth2
2. Choose one of their guilds (servers)
3. View/update bot settings (prefixes, logs, auto roles, welcome messages, etc.)
4. Save settings to a database
5. Ask the bot (or API) to apply changes in Discord

## Recommended architecture
Use a split architecture:

- **Frontend**: dashboard UI (Vue/React/Next/etc.)
- **Backend API**: handles OAuth, permissions checks, settings CRUD
- **Bot process**: the Discord client that applies settings and listens for events
- **Database**: stores per-guild settings

```text
Browser -> API server -> Database
              |
              v
         Discord bot
```

## Minimal security checklist
Before shipping, enforce these basics:

- Verify the user is in the guild they are editing
- Require `Manage Server` (or your chosen admin permission)
- Never expose your bot token in frontend code
- Store OAuth and bot secrets in environment variables
- Validate/sanitize all dashboard inputs

## Suggested MVP features
Build in this order:

1. OAuth login and guild picker
2. Read-only settings page
3. Edit one feature (for example: welcome channel)
4. Add audit logs (who changed what)
5. Add role-based restrictions for panel sections

## Example data model
A simple per-guild settings object is enough to start:

```json
{
  "guildId": "123456789012345678",
  "prefix": "!",
  "welcomeChannelId": "234567890123456789",
  "modLogChannelId": "345678901234567890",
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

## How this fits Custom Command workflows
If you use Custom Command features, you can still run a dashboard by:

- Storing configuration externally in your database
- Letting dashboard actions update those values
- Having bot commands read those values and apply behavior dynamically

This keeps UI management friendly while command logic stays flexible.
